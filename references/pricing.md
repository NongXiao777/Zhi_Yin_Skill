# 用明确成本计算渠道报价

现有“定价表”尚未提供，不能推断其中的运费、费率和利润公式。`pricing-quote` 使用一个明确的本地 JSON，把进货价、运费、包材费、其他成本和利润目标转换成报价。它不查询行情、不修改商品。

```powershell
python scripts/zhiying.py pricing-quote --file examples/pricing-input.json
```

示例全部是合成数字，不代表任何平台费率或真实商品。所有金额先统一币种；需要换汇时用用户确认的汇率预先换算，再填写成本。运费填写匹配目的地、物流渠道和计费重量的每件金额。缺少费用时先取得报价或明确填写 0，程序不会自动猜值。

| 字段 | 含义 |
|---|---|
| `currency` | 所有金额共用的三字母币种 |
| `unit_cost` | 每件进货成本 |
| `shipping_cost` | 每件已确定的运费 |
| `packaging_cost` | 每件包材成本 |
| `other_cost` | 其他每件固定成本，明确为零时填 0 |
| `platform_fee_rate` | 按销售价收取的费率，0.15 表示 15% |
| `target_profit` | 每件目标利润金额 |
| `target_margin` | 可替代 `target_profit`，利润占销售价的比例；两者只能填一个 |

四项成本之和为 C，费率为 f。金额利润目标 P 的最低售价为 `(C + P) / (1 - f)`；利润率目标 m 的最低售价为 `C / (1 - f - m)`。这里的利润仅按输入的成本与费用计算，未填入的税费、退款损失等不会自动纳入。费率及利润率必须使分母大于 0。

程序选择不低于最低售价的最小 `.49`、`.89` 或 `.99` 尾数，并返回报价、预计费用、输入范围内的利润和是否达到目标。例如合成输入总成本 13.00、费率 0.15、目标利润 4.00，最低售价 20.00，尾数报价 20.49。输入文件保持原样。

`channel_base_price` 和 `current_surcharge` 是可选人工比较值。程序只返回渠道报价差额和原始加价，不推导新 `money`。智赢的 `money` 是变体加价，`sale_price` 是分销单价，它们如何换算成最终渠道价仍待核验。

用户明确指定加价 `0.30 → 0.40` 时，可以用 `--adjust-surcharge EXACT_KEY 0.10`；明确指定 `0.50` 时可以用 `--set-surcharge EXACT_KEY 0.50`。先读到该商品的真实变体键，再按用户确认的目标提交，保存后读回核对。尾数报价本身不是修改加价的依据。
