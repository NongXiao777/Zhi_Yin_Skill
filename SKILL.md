Run `scripts/zhiying.py` with Python 3.9+ and use `<command> --help` for flags. Keep user-facing summaries focused and save complete source and preview results when the workflow uses them for verification or recovery.

Use authorized browser or CLI transports for live product operations and explicit local files for offline work. Keep screenshots read-only. Desktop diagnostics are independent of product editing.

Use the user's ordinary Chrome profile and logged-in ERP tab by default. Reuse the persistent connection and its valid page and worker IDs. Relocate targets when an ID is missing or stale. If Chrome requires first-time approval, make one connection request and wait for it to finish. Launch independent Chrome with a separate profile only when the user explicitly requests independent Chrome. Before launching, state that it is independent Chrome and explain that it has a separate login session. See [browser-workflow.md](references/browser-workflow.md).

If a client update causes `unsupported_client_version` or native reflection failures, run `client-diagnose --symbols`. Use the DLL hashes and RPC candidates to repair the local profile following [client-update.md](references/client-update.md). Use the same installation for diagnostics, synthetic probes, loopback tests, login and the first product read.

- For the complete sourcing, packaging, pricing and copy workflow, read [operation-workflow.md](references/operation-workflow.md). Quote supplied costs with `pricing-quote`; read [pricing.md](references/pricing.md). Final channel price and ERP variant surcharge remain separate.
- When native/TCP is selected, before reusing a session after a client update, run `login-status` with the same `--app` path. If Work or User changed or the session has no recorded hashes, use `login-native --if-needed` and have the user sign in directly in the vendor window. For an expired session or an explicit fresh login, run `login-native`. Read [login.md](references/login.md) for terminal login and session behavior; a working ERP browser login does not require this native step.
- Default to AliExpress when choosing a collection source. Explain the concrete reason and drawback before switching transports.
- Retrieve source data for collection-only requests, fill New when asked for a draft, and create a numbered Product Collection record when asked to add it to Product Collection. Follow [aliexpress-import.md](references/aliexpress-import.md) and generate calls with `scripts/browser_call.py`. Transfer to My Products is a separate requested action.
- For edits to existing products, default to the browser read/preview/apply/verify workflow in [browser-product-edit.md](references/browser-product-edit.md). Verify through the same product source. If the product has more than 50 variants, report the total and ask the user to check the variants outside the browser readout.
- Use `status`, `launch`, or `routes` for client diagnostics. On explicit request for a window check or activation, use `window-status` or `window-focus`.
- For the exe's embedded-browser 单个采集 displayed as `New`, use `collected-cache-list` with an optional `--match`, then `collected-cache-get --source-id ID`. Web New drafts use the browser import helper. `New` is a draft state, never a numeric product ID. See [collection-cache.md](references/collection-cache.md).
- Run `collected-transport-probe` for offline native encoding checks. My Products uses `product-live-get` / `product-live-edit` (`sale.detail/update`); Product Collection uses `collected-product-live-get` / `collected-product-live-edit` (`spider.detail/update`). Keep reads, writes and confirmation on the same source. The built-in TCP transport uses installed DLLs and the protected session from login, or `ZHIYING_SESSION_FILE`. Use `--include-copy` to read English copy and `--copy-file` to change selected fields. Verify writes by reading through that transport. See [collected-product-api.md](references/collected-product-api.md) for the outer `id` versus native `sale_id` distinction.
- 保存后桌面显示可能延迟；以服务器读回结果为准，稍等并刷新页面，勿因界面暂未更新重复加价或追加文字。
- For interrupted browser saves, keep the original preview and use browser `verify` and same-source readback before any further write. Use the [browser edit workflow](references/browser-product-edit.md) for an explicitly requested rollback when it supports the original values. When using a CLI transport, see [product-plans.md](references/product-plans.md) for durable plans. Check an uncertain CLI write with same-source `live-get`; `product-restore` can write original values and is for a requested rollback.
- Use `collected-product-get` and `collected-product-edit` for supplied local JSON snapshots. Read [erp-products.md](references/erp-products.md) for English introduction, per-variant `money` and .49/.89/.99 channel quotes.
- For local ERP product tables, use `erp-product-get` to select by product number and `erp-draft-preview` to review package fields and variant prices. Read [erp-products.md](references/erp-products.md) for columns and rules.
- For Amazon.com copy, including missing ERP descriptions, read [listing-workflow.md](references/listing-workflow.md). Validate the five copy fields with `listing-copy-check`. For product images, read [listing-images.md](references/listing-images.md).
- A downloaded Sales and Traffic JSON uses `traffic-summary --file report.json`. Filter by `--asin` or `--sku`, or use `--by date` for the report's date aggregates.
- Use [sp-api.md](references/sp-api.md) when the user requests online Amazon operations. `listing-preview` validates a draft. Amazon publishing is outside the default workflow. Create a report only when asked to request new data.

For traffic interpretation or connector research, read [amazon-organic.md](references/amazon-organic.md). Sales and Traffic covers all page traffic. Profit and stop-loss decisions require costs, fees and the seller's thresholds.
